# 桃源温泉乡 · AI 温泉经营游戏

欢迎来到桃源温泉乡。

这是一款给 AI 玩家游玩的轻量经营游戏：你会接手一间山里的小温泉，从露天汤池开始，慢慢建造新设施、接待客人、应对天气和突发事件，解锁成就，也可能遇见一些奇怪又热闹的隐藏剧情。

随机事件会按日常经营、顾客故事、天气、运营事故和稀有彩蛋分层出现。特殊名人只会通过预约与连续剧情来访，不会挤占普通客流。

你看不到完整规则书，也看不到隐藏成就条件。请像真正的经营者一样，根据每天公开的状态、日志和直觉做决定。

## 你可以做什么

- 等待并结束当天，观察温泉乡自然运营
- 建造新设施，比如室内温泉、餐厅、休息厅
- 升级已有设施，提高收入和满意度
- 安排打扫、换水、补货等维护工作，处理蟑螂、水质和库存危机
- 暂停营业进行深度清洁并处理虫害，或安排一次不保证提高工作效率的员工聚餐
- 处理捡到的钱包
- 收集公开成就和隐藏成就

## 快速开始

官方裁判服务器负责持久保存存档、结算事件、判定成就，并隐藏完整规则。

```bash
BASE=https://taoyuan-hotspring.onrender.com

curl -s $BASE/health
# {"ok":true,...}

SID=$(curl -s -X POST $BASE/new -H 'Content-Type: application/json' \
      -d '{"detail":"compact"}' | python -c "import sys,json;print(json.load(sys.stdin)['session_id'])")

curl -s "$BASE/state?session_id=$SID&detail=compact"

curl -s -X POST $BASE/act -H 'Content-Type: application/json' \
     -d "{\"session_id\":\"$SID\",\"action\":\"build\",\"facility\":\"室内温泉\"}"
curl -s -X POST $BASE/act -H 'Content-Type: application/json' \
     -d "{\"session_id\":\"$SID\",\"action\":\"upgrade\",\"facility\":\"露天温泉\"}"
```

> 注意 `session_id` 是这一局的存档钥匙，**一定要自己记下来**（建议写进本地笔记文件），
> 换窗口或隔天继续都用同一个 id 请求 `/state` 和 `/act`。

如果你要本地跑私有裁判服务器：

```bash
python server.py            # 默认 http://127.0.0.1:8765
```

## 可用行动

- `wait`：等待并用完今日剩余 AP，然后结算当天
- `end_day`：主动结束当天并结算，尚未使用的 AP 作废
- `build`：建造设施，例如 `facility="室内温泉"`
- `upgrade`：升级已有设施，例如 `facility="露天温泉"`；每次提升 1 级，最高 `Lv.10`。`Lv.6 / Lv.8 / Lv.10` 会成为**镇店名物**，额外涨人气与声誉。`Lv.6` 起进入深度升级区间，成本指数上升，是后期金币的去处之一
- `invest`：大额投资，消耗 3 AP，按固定顺序进行。一次砸一大笔钱换客流、水质、评选声望或设施收益，是后期金币的主要去处。当前可投项目见状态里的 `investments.next`
- `clean`：打扫卫生，消耗 1 AP
- `resolve_complaint`：处理所有等待整改的客诉，消耗 1 AP 和对应补偿金；只有整改完成后才会恢复声誉
- `community_service`：卫生与水质合格时开展社区服务，消耗 1 AP 和 120 金币，恢复少量声誉，冷却 3 天
- `reply_review`：回复一条尚未回应的中差评，消耗 1 AP；声誉越高、实际整改越好，顾客越可能提高一星
- `compensate_review`：退款、赠券并邀请差评顾客复访，消耗 1 AP；花费随经营规模变化，可提高星级与声誉
- `apologize_review`：老板亲自登门道歉，消耗 1 AP，**不花钱**，把一条中差评抬高一星、声誉 -1，冷却 5 天。这是星级下跌闭环的兜底出口——破产玩家也能用
- `solicit`：主动揽客，消耗 1 AP，每天限一次。三档可选：
  - `mode="扫街"`：免费，客流 +12% 持续 1 天，不加人气
  - `mode="传单"`：30 金币，客流 +25% 持续 2 天，人气 +1
  - `mode="团购"`：90 金币，客流 +50% 持续 3 天，人气 +2
- `promote_listing`：在「桃源点评」购买三天曝光，消耗 1 AP 和 200 金币；只增加评价数量，不保证好评
- `invite_reviewer`：邀请专业探店，消耗 1 AP 和 320 金币；评分由卫生、水质与库存决定
- `buy_fake_reviews`：雇请 1–100 位普通素人写五星评价，每条 100 金币、共消耗 1 AP；会进入均分，少量不易触发审核
- `buy_water_army`：投放 20–500 个低权重水军账号，每个 2 金币、共消耗 1 AP；不改变均分，只会三天内把部分真实差评挤出前排
- `inspect_water`：检查潜伏的水质问题，消耗 1 AP
- `regular_water`：常规换水，消耗 2 AP
- `deep_water`：彻底换水，消耗 3 AP 和 500 金币
- `restock`：补充日常库存，消耗 2 AP
- `make_video`：拍摄推广视频，消耗 1 AP。可选择老板自拍，或花费 120 金币邀请网红博主
- `pause`：暂停营业并深度清洁、清除已有虫害；停业当天不会滋生或传播虫害，行动会直接结束当天
- `story_choice`：处理特殊客人的剧情选择；不消耗 AP 或推进日期，选择后仍可安排当天经营。推荐同时提交 `guest` 和 `choice`；服务器也会兼容不同 AI 把合法选项放进 `story`、`facility` 或 `action` 的情况
- `team_build`：独立的整日员工聚餐；会自动暂停营业并结束当天，无需先执行 `pause`。提高默契，但不降低偷懒率或提高效率
- `return_wallet`：归还钱包
- `keep_wallet`：私吞钱包

## 每日 AP

- 工作日：共有 3 AP
- 周末/节假日：全员高强度协作，共有 4 AP
- AP 每天重置，不会累积；暂停营业会直接结束当天
- `hot_spring_act` 是单步经营入口。打扫、补货、换水、处理投诉或点评后，剩余 AP 会保留，可继续安排当天行动
- AP 用完、执行 `wait`、使用 `end_day`、暂停营业或执行整日行动后，才会结算客流、收入、衰减和随机事件
- `hot_spring_operate_day` 是早上一次提交的整天计划。提交后当天会统一结算，未安排的点数进入 `expired_ap` 并作废
- 日结后 `unused_ap` 固定为 0，`can_continue_today=false`；只有所有行动都失败、当天尚未推进时，`unused_ap` 才表示真正还能重新提交的点数
- 员工走神只影响打扫、换水、补货等维护行动，不影响扩建、装修和升级
- 指定员工时可填写 `worker="阿岚"`、`worker="小满"` 或 `worker="owner"`；指定员工不在岗时会明确拒绝，不会悄悄换人

`available_ap` 表示当天整个温泉乡的行动能力，并不是凭空赠送给老板的点数。

状态中的 `current_day_ap` 会显示当天是否已经开始、已用 AP、剩余 AP 和已完成行动。前 6 天属于渐进式新手期，随机事件密度会逐步提高；前三天不会出现直接停业或重罚的严重事故，第 7 天起恢复正常 65% 事件率和完整事件池。

## 桃源温泉榜：玩到什么程度算赢

经营游戏需要一个终点，否则钱攒到一定程度就没意义了。桃源温泉乡的目标是**把这座温泉乡做到天下第一**。

### 评选

每 12 天（每季末）评选一次，按八项综合打分：设施力、服务、口碑、人气、汤泉卫生、组合、客层、积累。名次越高，奖金、人气与声誉越好。

| 位阶 | 分数门槛 | 名次 |
|---|---|---|
| 榜外 | < 200 | — |
| 铜榜 | 200 | 150-200 |
| 银榜 | 340 | 80-149 |
| 金榜 | 480 | 30-79 |
| 白金榜 | 620 | 10-29 |
| 名泉百选 | 760 | 4-9 |
| 天下第一泉 | 880 | 2-3 |
| 桃源至尊 | 960 | 第 1 名 |

登顶【桃源至尊】即为**通关**。

状态里的 `guide_rank` 给出当前评分、各项得分与满分线、距下一档还差多少分、距下次评选还有几天。只列各项得分与满分线，**不提供加权公式**——知道该补哪一块就够了。`score/tier/rank` 是按当下数据的预估，正式名次与奖金在评选日确定，记录在 `history` 与 `best_rank/best_tier`。

### 终局

营业满 144 天（3 年）自动做终局结算，给出综合评级（S / A / B / C / D）与 Clear Points，之后仍可继续经营。评级由金币、榜单最好成绩、累计客人数、设施总等级、镇店名物数、组合数、投资数与成就共同决定。

参考实测（144 天 × 6 种子）：保守打法中位约 6.0k（C/D），常规打法约 12.6k（B~S），全力经营约 21.0k（A/S）。

### 后期金币去哪了

规模上去后收入增长快于支出，是这类游戏的通病。三条消耗路径：

- **深度升级**：设施最高 `Lv.10`，`Lv.6` 起成本指数上升，单个设施升满约需 21 万金币
- **大额投资**：六项递进投资，总计约 88 万金币，分别侧重客流、水质、评选声望、设施收益与名望
- **日常开销**：人工与设施维护随规模和设施等级同步上升

## 设施组合（相性）

设施之间会产生组合效果，**但整张组合表不会预先公布**——你建出对应设施才会「发现」它。这是本作最主要的探索内容之一，试组合本身就是玩法。

状态里的 `synergies` 字段会告诉你：

- `discovered`：已经发现的组合，含效果、当前状态和化解方向
- `undiscovered`：**还有几条组合没被发现**。这个数字是刻意留下的，用来提示你继续尝试
- `active_effects`：当前实际生效的总加成（收入倍率、满意度、每日人气）

组合的三条规则：

1. **负面组合可以化解。** 有些搭配会互相拖累（比如游戏厅的动静传到休息厅）。把相关设施升到 **Lv.3** 就能化解，负面组合不是惩罚，是「需要解决的问题」。
2. **停业会断链。** 组合要求的所有设施都在场且未停业才生效。所以停业的代价不只是少一份收入，而是整条组合链断掉。
3. **收益有上限。** 收入倍率最高 ×1.50，满意度最高 +25。这是为了防止把设施全建一遍就叠出失控的倍率——**挑组合比堆数量更重要**。

组合带来的满意度按乘法叠加（不会稀释），累计上限 +25；收入倍率叠乘后夹到 1.50。

## 经营成本

初始资金 `14000` 金币。前 12 天属于爬坡期，日收入会打 72 折；第 13–24 天打 86 折，之后恢复全额。这段折扣是为了让前期不至于一开局就失血过多，但**每日固定支出并不会因此消失**——所以前两周仍然需要主动揽客，而不是等着客流自己长出来。

每日支出不再只是固定小数目，而是由人工、设施维护、隐藏设施维护、水电、洗涤耗材、客人耗材、周末加班、周期合规费、天气成本和事故维修共同组成。高等级设施的维护费会加速上涨，因此后期仍需要保留现金、安排维护并控制扩张节奏。

建造和升级成功时会直接显示当前季节下该设施的预计每日维护费；这只是设施维护部分，人工、水电、布草和客耗仍会另行结算。

正常营业会按当日营业额扣除 `10%` 营业税；人气达到 80 后，旺铺附加税率为 `12%`。安全、消防、卫生、水质和重大客诉罚款会参考近期营业额与设施规模浮动，后期事故不再只是损失几十金币。

顾客投诉不会立即增加声誉。投诉发生时先退款并进入两天整改期；按时执行 `resolve_complaint` 才会恢复声誉，逾期则追加赔偿并形成公开投诉。

## 周转困难时的出路

账上金币低于 `30` 时，街坊会接济 `600` 金币应急，代价是声誉 `-2`、随机一处设施停业 1 天，冷却 20 天。这保证任何局面都不会彻底卡死，但接济只能续命，不能治病。

真正摆脱困境靠的是主动揽客，而不是等客流回升。破产状态下仍然能做的三件事：

- `solicit` 的「扫街」档完全免费，每天都能做一次，直接给当天客流加成。
- `apologize_review` 不花一分钱，5 天一次，能把一条差评抬高一星，打断「星级跌 → 客流少 → 更没钱 → 星级更跌」的闭环。
- 换水和补货在账上没钱时可以**赊账**执行，日志会标注「老板自己挑水」「向老供应商挂账」。水质和库存一旦归零就再也修不回来，所以这两项永远不该因为缺钱而卡住。

补偿、邀评、推广这些要钱的手段，等现金流转正之后再用。

## 停业整改

卫生低于 `30` 或水质低于 `20` 会被勒令停业：当天不接待新客、没有营业收入，但人工和维护费减半。复业条件是**两项同时回到安全线以上**，状态提示会显示当前值和还差多少。

停业最多持续 `5` 天，期满强制复业并扣 `10` 点声誉。这保证不会出现「停业 → 零收入 → 修不起 → 继续停业」的无限螺旋——实测修复前有过连续 40 天停业、玩家每天只能空转的局面。

停业期间不会触发新的随机事件，也不会刷新大佬访客，但日常维护照常进行。

## 隐患与客诉不是一回事

`pending_issues` 是混合列表，里面既有客诉（`kind=customer_complaint`），也有水质、污染、卫生、虫害等其他类型。每一项在状态里都带 `suggested_action` 字段，标明该用什么动作处理。

`resolve_complaint` **只处理客诉**。如果剩下的都是水质类隐患，它会明确回复「另有 N 项非客诉隐患：『XXX』需用 deep_water」并提示不要重复调用。

这一点对 AI 玩家尤其重要：只看到「有隐患」就反复调用 `resolve_complaint`，会对着一个永远失败的动作空转几十天，把每天的 AP 全部耗光。

## 赤字与赊账

金币允许为负，最多赊 `800` 金币，超出部分会被清算。赊账期间：

- 声誉惩罚只在首次赤字时扣 `5`，之后每 `10` 天才再扣一次，不会每天重复。
- 换水（5 金币）、补货（20 金币）等刚需维护照常可用。
- 建造、升级、营销这类非必要支出仍然要求账上有钱。

这样做的理由：旧逻辑把金币直接夹到 0，于是第二天任何一笔支出都会让它再次变负，`声誉-8` 每天稳定触发一次——实测 60 天里这一项就扣掉 504 点声誉，占全部扣减的 79%。玩家不是经营失败，是被重复惩罚压死的。

## 桃源点评

MCP 连接后会出现独立工具 `hot_spring_review`。不必在通用经营动作里寻找，直接选择以下六种点评行动：

- `reply_review`：认真回复一条尚未回应的中差评
- `compensate_review`：退款、赠券并邀请差评顾客复访
- `apologize_review`：老板亲自登门道歉（免费，5 天一次，抬高一条差评一星、声誉 -1）
- `promote_listing`：购买三天曝光，只增加评价数量，不保证好评
- `invite_reviewer`：邀请专业探店，按真实经营状态评分
- `buy_fake_reviews`：按每条 100 金币雇请普通素人代写，评价会进入均分
- `buy_water_army`：按每个账号 2 金币投放低权重水军，只能遮住前排差评，不能真正洗高评分

点评星级、声誉和人气是三套独立数值，但会有限互相影响：

- 人气提高顾客离店后发布评价的概率，不会直接提高星级。
- 声誉提高认真回复差评的成功率，不会直接修改平均评分。
- 星级由顾客满意度、卫生、水质、虫害和设施状态决定。
- 真实好评小幅增加声誉与人气；真实差评会降低信任和客流。
- 付费推广只购买曝光；邀请探店仍可能因为经营状态差而得到低分。
- 素人代写会累积「异常指数」。单次只买 1–2 条的审核概率较低；14 天内集中购买越多，异常指数和审核概率会非线性上升。
- 水军账号价格低、出现快、权重也低。它们不进入平均星级，只会在三天内把部分未解决差评挤出首页；投放数量越大，越容易被平台立即识别。
- 平台查出任一类异常操作后，会删除代写评价、清除水军、按近期营业额罚款、降低声誉与人气，并限流三天。

状态中的 `review_platform` 会展示平均星级、星级分布、近期评价、待处理差评、推广天数、异常指数和累计点评支出。

状态里的 `daily_expense` 是总支出，`expense_breakdown` 会列出各项明细。

## 精简状态

MCP 工具默认返回 `detail="compact"`，只展示当日变化、关键数值、待处理事件和近期发现，节省上下文。需要检查住客簿、完整历史等资料时，传入 `detail="full"`。

随机事故可能让设施短暂停业或产生维修费，但不会永久删除已经建成的设施。

## 历史日志

服务器会随存档保留最多 5000 条经营日志，每条都记录回合、季节、天气和事件内容。普通状态仍只显示最近 5 条，避免日常回复过长。

排查旧事件时使用 MCP 工具 `hot_spring_get_history`，支持：

- `page`、`page_size`：分页读取，每页最多 100 条
- `since_turn`：只查看指定回合之后的记录
- `search`：按“水质”“蟑螂”“投资人”等关键词筛选
- `order`：选择 `newest` 或 `oldest`

升级前已经被旧版本覆盖的日志无法恢复；升级时会自动迁移旧存档中仍保留的最近记录。

更多细节见 [API.md](API.md)。
